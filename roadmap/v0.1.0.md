# v0.1.0: Complete the first public beta

## Intent

Make the initial feature set usable as a small game framework rather than a
collection of promising subsystems. Close the known runtime and core-toolkit
gaps, prove the systems work together, and make the release's supported
behavior measurable.

## Feature set

### Runtime diagnostics

- [ ] Add an opt-in development overlay for FPS and TPS. It must be possible
  to disable it in normal game builds, and it must not change simulation
  behavior.

### Content and gameplay basics

- [ ] Add font asset loading and text rendering through the engine's normal
  asset and rendering path. Keep this to drawing text; defer widget layout
  and interactive UI.
- [ ] Give non-looping animations an observable completion state. Define its
  reset/restart behavior and ensure completion is stable after the last frame
  instead of representing completion only as a paused animation.
- [x] Ship the timer component and reconciler: one-shot and repeating
  timers as component state. Timers advance with the fixed tick while
  running; completion is observed as a tick stamp - JustCompleted
  for the edge, CompletedOn for the record - with no events. Each
  timer is its own entity, so one actor can hold any number of them.
- [x] Ship the collision stack: touch-inclusive shape predicates in geom,
  a broad-phase spatial grid, a rotation-aware narrow phase for boxes and
  circles, and the collision lifecycle as Contacts component state -
  enter/stay/exit are edges a game derives, no event bus. Detection only:
  collision response, rigid-body physics, and a solver stay out until a
  consumer asks. (#51)

## Release gates

- [ ] Tests cover the new timer, collision, text/font, and animation
  completion contracts, including boundaries and lifecycle transitions.
- [ ] `go vet ./...` is a release gate. Publish coverage for the core,
  scheduler, and default runner; set and meet a coverage threshold based on
  that baseline rather than adopting an unverified blanket percentage.
- [ ] Add benchmarks for the ECS, scheduler, asset loading, and
  rendering-related hot paths; establish baselines before setting
  performance budgets.
- [ ] Regression-check default-runner eager and streaming audio playback and
  cleanup. The current provider is wired; new pan control belongs to v0.2.0.
- [ ] Add or update one end-to-end example that combines the supported
  foundation features without duplicating subsystem-only examples.
- [ ] Every new public feature has Go documentation, a guide or guide
  section, and a focused runnable example where appropriate.
- [ ] Verify the documented build and test commands from a clean checkout.

## Explicitly not in this target

Game-level pause and time scaling, camera rotation and bounds, audio panning,
entity hierarchy, asynchronous/batch asset loading, general signals/events,
and general UI are not part of this feature set. Keep the release focused on
the gaps above and avoid importing the old engine's architecture wholesale.
