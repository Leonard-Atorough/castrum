# Migrating from 0.1.0 to 0.2.0

The migration for a game upgrading from Castrum 0.1.0 covers its camera setup
and one mechanical rename. If your game uses the engine-provided camera without
changing its zoom or framing, and neither names `asset.Server` nor calls
`asset.New`, no code changes are required.

## Move camera zoom to the transform

In 0.1.0, `render.Camera` stored zoom, while `core.Transform` stored the
camera's position:

```go
render.Camera{Primary: true, Zoom: 2}
core.Transform{Position: position}
```

In 0.2.0, `render.Camera` contains camera framing options, and the transform
stores position, rotation, and zoom. Set zoom through a uniform transform
scale:

```go
render.Camera{Primary: true}
core.Transform{
	Position: position,
	Scale:    geom.Vector2{X: 2, Y: 2},
}
```

Keep the X and Y scale equal for cameras. A zero scale component means zoom 1;
negative or non-uniform camera scale is invalid and causes camera collection
to return an error. When creating a camera with `render.SpawnCamera`, pass the
initial position and zoom as arguments; zero zoom selects the default of 1,
while a negative or non-finite zoom is rejected during setup:

```go
camera, err := render.SpawnCamera(
	g.World(),
	render.Camera{Primary: true},
	position,
	2,
)
if err != nil {
	return err
}
```

To change zoom after setup, update both scale components on the camera's
`core.Transform`:

```go
if err := camera.Update(g.World(), func(t *core.Transform) {
	t.Scale = geom.Vector2{X: zoom, Y: zoom}
}); err != nil {
	return err
}
```

Remove any `Zoom` field from `render.Camera` literals and replace reads of
`Camera.Zoom` with the camera transform's scale. `render.CameraView.Zoom`
remains the resolved zoom for a rendered frame.

## Optional framing features

The 0.2.0 `render.Camera` adds `Anchor` and `Bounds`, and camera rotation comes
from `core.Transform.Rotation`. These features are optional:

- `Anchor` defaults to `(0, 0)`, keeping the camera position at the viewport
  center. Its components must be between `-0.5` and `0.5`; `(-0.5, -0.5)`
  places the camera position at the viewport's top-left.
- `Bounds` defaults to an empty, unbounded view. A non-empty rectangle clamps
  the resolved camera view to that world-space region after transform
  interpolation.
- `Rotation` defaults to zero and is measured in radians. It is interpolated
  with the camera transform like position and scale.

The [camera guide](../guides/camera.md) covers anchors, rotation, bounds,
zoom validation, and reading the resolved camera view.

## Rename asset.Server to asset.Loader

In 0.2.0 the asset package's type is `asset.Loader` and its constructor is
`asset.NewLoader`. Every operation on the type is a load-side operation - `Load`,
`Open`, `LoadReader`, decoder registration, and the atlas registry - and the
name now says so. The change is mechanical:

```go
// 0.1.0
server, err := asset.New(files)
```

```go
// 0.2.0
loader, err := asset.NewLoader(files)
```

The engine provides the loader as a world resource where the server used to
be, so resource lookups change with it:

```go
// 0.1.0
server := g.World().MustResource[*asset.Server]()
```

```go
// 0.2.0
loader := g.World().MustResource[*asset.Loader]()
```

Replace every `asset.Server` reference with `asset.Loader` and every
`asset.New` call with `asset.NewLoader`. Method names, option names, the cache
behavior, and the resource registration are unchanged; only the two names
move.

## Unchanged

No other 0.1.0 migration action is required. In particular, the engine's
default camera is still created automatically and remains at the world origin
with zoom 1. User-spawned primary cameras continue to take precedence over
that default.
