# Migrating from v0.3.0 to unreleased

## Migrate audio

The unreleased audio API separates playback settings from media selection. Code that stores audio IDs in `Source`, constructs sources with an audio ID, or calls `OneShot` without a clip must be updated. Other playback settings such as volume, group, loop, pause, and load remain on `Source`.

## Migrate timers to the gametime package

The unreleased API moves the `timer` package into `gametime`, the home of the engine's time work, and exposes the fixed loop's state as the `gametime.Simulation` resource. Update imports and the renamed identifiers; timer types and semantics are unchanged:

```go
import "github.com/Leonard-Atorough/castrum/gametime"

t := gametime.NewTimer(3*time.Second, true)          // was timer.NewTimer
name := gametime.TimerSystemName                     // was timer.SystemName; value "engine.timer" is unchanged
system := gametime.NewTimerSystem()                  // was timer.NewSystem
groups := gametime.NewGroups()                       // was timer.NewGroups
```

`Timer`, `Groups`, and `Completed` keep their names and behavior; only the package and the two renamed identifiers (`SystemName` → `TimerSystemName`, `NewSystem` → `NewTimerSystem`) change. The `Simulation` resource is new in the same package: `game.Pause`, `Resume`, `Paused`, `TimeScale`, and `SetTimeScale` now read and write it, so simulation time is readable by systems and savable with the world. See the [time guide](../guides/time-control.md).

## Move media selection out of `Source`

In v0.3.0, `Source` both selected an asset and configured its playback:

```go
source := audio.NewSource(AssetMusic)
source.Group = audio.GroupMusic
source.Loop = audio.LoopForever
_, err := world.NewEntity(source)
if err != nil {
	return err
}
```

In the unreleased API, `audio.NewSource` takes no arguments and returns playback settings. Add a separate `Clip` component to select one asset:

```go
source := audio.NewSource()
source.Group = audio.GroupMusic
source.Loop = audio.LoopForever
_, err := world.NewEntity(source, audio.Clip{Audio: AssetMusic})
if err != nil {
	return err
}
```

Remove reads and writes of `Source.Audio`; read or update `Clip.Audio` instead. Changing the clip selection still starts the selected asset from the beginning. A playing entity must have exactly one selector: `Clip` or `Playlist`. A source without either selector does not play, and adding both is an error.

## Update one-shot calls

`OneShot` now takes the selected clip as a separate argument. Replace calls like:

```go
shot := audio.NewSource(AssetMagic)
_, err := audio.OneShot(world, shot)
```

with:

```go
shot := audio.NewSource()
_, err := audio.OneShot(world, shot, audio.Clip{Audio: AssetMagic})
```

One-shots still must not loop. `OneShot` rejects spatial sources; use `audio.OneShotAt(world, source, clip, position)` for a fire-and-forget spatial sound. `OneShotAt` marks the source spatial, so the world must provide a `*audio.Listener`; position-based adjustment occurs only when that listener is enabled.

## Use playlists for track sequences

`Playlist` is a new selector for sequential playback; it replaces application code that previously changed a source's asset ID to advance between tracks. Create a playlist from asset IDs and add it alongside the source:

```go
source := audio.NewSource()
source.Group = audio.GroupMusic
playlist := audio.NewPlaylist([]asset.ID{AssetIntro, AssetLevel})
playlist.Repeat = audio.RepeatAll
_, err := world.NewEntity(source, playlist)
if err != nil {
	return err
}
```

Use `Playlist.Next`, `Previous`, or `Seek` to select a track. A playlist must contain at least one non-empty asset ID. `Source.Loop` repeats the current asset; leave it at `LoopNone` when the playlist should advance after each track. See the [unreleased audio guide](../guides/audio.md) for playlist editing, spatial audio, and lifecycle details.
