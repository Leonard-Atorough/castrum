# Migrating from v0.3.0 to unreleased

## Migrate system registration and phases

Replace `AddSystemToGroup` with `AddSystem` and `castrum.InGroup`:

```go
// Before: g.AddSystemToGroup(core.PhaseFixed, "gameplay", "move", moveSystem)
if err := g.AddSystem(core.PhaseFixed, "move", moveSystem, castrum.InGroup("gameplay")); err != nil {
	return err
}
```

For an empty group, omit `InGroup` to leave the system ungrouped. Existing ordinary `AddSystem` calls still work, but its variadic signature changes its method type; update interfaces or method values that require the old signature. Names must now be unique within each phase, and duplicate names return errors. Invalid phases and startup-phase registrations after `Startup` begins also return errors.

The numeric values of existing phases changed. If saved data or configuration stores phase numbers, map each v0.3.0 value once with this lookup, not in sequence: pre-startup `3` to `0`, startup `0` to `1`, pre-frame `4` to `3`, frame `1` to `4`, and fixed `2` to `7`. Prefer named phase constants in code. The new pre- and post-phases and relative ordering options are described in [Scheduling systems](../guides/system-scheduling.md).

## Migrate audio

The unreleased audio API separates playback settings from media selection. Code that stores audio IDs in `Source`, constructs sources with an audio ID, or calls `OneShot` without a clip must be updated. Other playback settings such as volume, group, loop, pause, and load remain on `Source`.

## Remove system-enabling options

The timer, collision, and animation systems are now always registered: their work is declared by component presence, so the component is the registration and an unmatched system costs an empty query per tick. Remove `castrum.WithTimer`, `castrum.WithAnimation`, `castrum.WithCollision`, and `castrum.WithDefaultSystems` from `castrum.New` calls - declaring a `Timer`, `Collider`, or `Animation` component enables the behavior. `WithScenes` and `WithState` remain: scenes and state machines are instance-driven, and the options construct their resources.

## Migrate timers to the gametime package

The unreleased API moves the `timer` package into `gametime`, the home of the engine's time work, and exposes the fixed loop's state as the `gametime.Simulation` resource. Update imports and the renamed identifiers; timer types and semantics are unchanged:

```go
import "github.com/Leonard-Atorough/castrum/gametime"

t := gametime.NewTimer(3*time.Second, true)          // was timer.NewTimer
name := gametime.TimerSystemName                     // was timer.SystemName; value "engine.timer" is unchanged
system := gametime.NewTimerSystem()                  // was timer.NewSystem
groups := gametime.NewGroups()                       // was timer.NewGroups
```

`Timer`, `Groups`, and `Completed` keep their names and behavior; only the package and the two renamed identifiers (`SystemName` → `TimerSystemName`, `NewSystem` → `NewTimerSystem`) change. Two resources are new in the same package: `Simulation` (the fixed loop's tick, pause, scale, and tick-interval state - `game.Pause`, `Resume`, `Paused`, `TimeScale`, and `SetTimeScale` now read and write it) and `Real` (wall-clock elapsed time, unaffected by pause and scale, plus the runtime-adjustable `MaxFrameTime` clamp). Simulation time and real time are readable by systems and savable with the world. `ctx.DeltaTime` is unchanged: it mirrors `Simulation.Delta` during fixed updates and the clamped real delta during frame updates. See the [time guide](../guides/time-control.md).

## Move media selection out of `Source`

In v0.3.0, `Source` both selected an asset and configured its playback:

```go
source := audio.NewSource(AssetMusic)
source.Group = audio.GroupMusic
source.Loop = audio.LoopForever
_, err := world.NewEntity(source)
if err != nil {
	return err
}
```

In the unreleased API, `audio.NewSource` takes no arguments and returns playback settings. Add a separate `Clip` component to select one asset:

```go
source := audio.NewSource()
source.Group = audio.GroupMusic
source.Loop = audio.LoopForever
_, err := world.NewEntity(source, audio.Clip{Audio: AssetMusic})
if err != nil {
	return err
}
```

Remove reads and writes of `Source.Audio`; read or update `Clip.Audio` instead. Changing the clip selection still starts the selected asset from the beginning. A playing entity must have exactly one selector: `Clip` or `Playlist`. A source without either selector does not play, and adding both is an error.

## Update one-shot calls

`OneShot` now takes the selected clip as a separate argument. Replace calls like:

```go
shot := audio.NewSource(AssetMagic)
_, err := audio.OneShot(world, shot)
```

with:

```go
shot := audio.NewSource()
_, err := audio.OneShot(world, shot, audio.Clip{Audio: AssetMagic})
```

One-shots still must not loop. `OneShot` rejects spatial sources; use `audio.OneShotAt(world, source, clip, position)` for a fire-and-forget spatial sound. `OneShotAt` marks the source spatial, so the world must provide a `*audio.Listener`; position-based adjustment occurs only when that listener is enabled.

## Use playlists for track sequences

`Playlist` is a new selector for sequential playback; it replaces application code that previously changed a source's asset ID to advance between tracks. Create a playlist from asset IDs and add it alongside the source:

```go
source := audio.NewSource()
source.Group = audio.GroupMusic
playlist := audio.NewPlaylist([]asset.ID{AssetIntro, AssetLevel})
playlist.Repeat = audio.RepeatAll
_, err := world.NewEntity(source, playlist)
if err != nil {
	return err
}
```

Use `Playlist.Next`, `Previous`, or `Seek` to select a track. Each track must be a non-empty asset ID. An empty playlist selects nothing and releases old playback on reconciliation; adding a track later starts that selection under the existing pause rules. `Source.Loop` repeats the current asset; leave it at `LoopNone` when the playlist should advance after each track. See the [unreleased audio guide](../guides/audio.md) for playlist editing, spatial audio, and lifecycle details.
